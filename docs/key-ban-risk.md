# 阵容关键干员禁用风险补丁

以 v0.9.8 / 229c5de 为基线。复用 `LineupMember.key`，不改变存储格式、共享码、云同步或识别逻辑。

排序使用风险组而非加权分数：暂未发现冲突、普通成员受限、目标盟约受限、关键干员受限。同组按关键被禁人数、受限目标盟约数、普通被禁人数，最后保留原顺序。已选目标依然置顶，但明确标注不代表推荐。

评估对象是成型阵容，和旧版本一致。阶段的早期关键干员不自动提升为整局必须条件。关键只是用户定义的重要成员，受限不等于绝对不能玩；本补丁不自动推断替代干员。旧配置没有关键标注时明确提示不能判断核心完整性。

识别尚未发生、等待详情、尚未扫描禁用列表、无分组、未完整分组、未识别格子、推测格子都会提示需核验。即使未检测到这些缺口，文案也只表达基于已知禁用信息，不保证可用。

验证：
- `npm --prefix src/ui test`：需要 Node 22.18+ 或 24（原生 TypeScript 类型擦除），涵盖关键/普通排序、盟约限制、旧配置、未知识别、阶段范围。
- `npm --prefix src/ui run check`
- `npm --prefix src/ui run build`
- Windows 原生宿主/实际截图验证仍需进行；本补丁没有更改 .NET 宿主。

## Fork 试用版 v0.9.8-keyban.1

- 仅发布在 KomachiSion/StrongholdAssistant，不是上游正式版本。
- Windows 10/11 x64，自包含 .NET；需要 WebView2（Windows 11 通常自带）。下载 ZIP 后全部解压，运行 StrongholdAssistant.exe。
- 与原版共用 `%AppData%\StrongholdAssistant`，请先使用原版导出备份，关闭原版后再启动试用版，勿同时运行两个版本。
- 此构建禁止应用内自动/手动更新，以免被上游或 Mirror酱版本覆盖。设置里关闭自动检查可隐藏启动时的更新提示；后续从此 fork 的 Releases 手动下载。
- 无核心标记的旧阵容会提醒无法判断核心完整性；同风险等级优先已配置关键干员的阵容，不假设未标记等于安全。
- 已通过前端回归测试与生产构建；Svelte 类型检查存在上游原有的 bridge.ts、mock.ts 两项 roster 等接口缺失，不属于本补丁新增错误。
- Windows CI 执行原生发布、ZIP 回读校验和 15 秒启动存活检查；这不等于已完成真实游戏识别、完整 GUI 或干净 Windows 11 机器验收。
- 试用重点：编辑阵容并标记关键干员，分别比较关键被禁和普通成员被禁；核对红色说明和排序；不完整识别应保留核验提示。
